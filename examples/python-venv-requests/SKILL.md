# Python virtual environment + pinned requests

> Verification: 6/6 steps executed successfully on 2026-11-26 in a throwaway folder on Windows (Git Bash, Python 3.12.4), with the `.venv/Scripts/` paths from Variants.

At the end: an isolated `.venv/` folder, `requests` 2.32.3 installed in it, and a `requirements.txt` that recreates the environment identically.

## Prerequisites
- Python 3 available as `python3` [t=0:08]
- Terminal open at the project root (`~/project` in the video) [t=0:05]

## Steps

### 1. Create the virtual environment [EXECUTE]
```bash
python3 -m venv .venv
```
✔ Success: no error message, a `.venv/` folder exists. [t=0:08]

### 2. Use the environment's own python and pip [EXECUTE]
The video activates the environment with `source .venv/bin/activate` [t=0:19]. Activation only lasts for one shell session, and each Claude Code shell call starts fresh, so call the environment's tools by path in every later step: `.venv/bin/python` and `.venv/bin/pip`.
```bash
.venv/bin/python -c "import sys; print(sys.prefix)"
```
✔ Success: the printed path ends in `.venv`.

### 3. Install a pinned version of requests [EXECUTE]
```bash
.venv/bin/pip install requests==2.32.3
```
The exact version comes from the screen: the narration says "request, version 2.32", the screen shows `requests==2.32.3` [t=0:23].
✔ Success: the last line contains `Successfully installed … requests-2.32.3`, with the certifi, charset-normalizer, idna, urllib3 dependencies. [t=0:23]

### 4. Check the install [EXECUTE]
```bash
.venv/bin/python -c "import requests; print(requests.__version__)"
```
✔ Success: prints `2.32.3`. [t=0:31]

### 5. Freeze the dependencies [EXECUTE]
```bash
.venv/bin/pip freeze > requirements.txt
```
[t=0:36]

### 6. Check the file [EXECUTE]
```bash
grep requests requirements.txt
```
✔ Success: prints `requests==2.32.3`. [t=0:45]

## Variants
- ➕ added: on Windows, the tools live in `.venv\Scripts\` instead of `.venv/bin/` (e.g. `.venv\Scripts\pip install requests==2.32.3`), Python is usually `python` rather than `python3`, and interactive activation in PowerShell is `.venv\Scripts\Activate.ps1` (source: https://docs.python.org/3/library/venv.html).
- ➕ added: recreate the environment elsewhere → `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt` (same source).
- Working by hand in an interactive terminal: activate once with `source .venv/bin/activate` [t=0:19], then plain `pip` and `python` work as in the video.
- Another requests version: replace `2.32.3` in step 3; the video only covers this one.

## Troubleshooting
- Interactive terminal: `(.venv)` does not appear after `source .venv/bin/activate` → it was run with `sh` instead of `bash`/`zsh`: use `. .venv/bin/activate`. (➕ added, same source)
- `.venv/bin/pip: No such file or directory` → on Windows, use `.venv\Scripts\pip` (see Variants), or step 1 has not run.
- ➕ added: add `.venv/` to `.gitignore` so the environment is not versioned.

## When the user returns
- Same session: `.venv/` already exists, so skip step 1 and run step 4 to confirm requests is still installed.
- New session: run step 4 first. If it prints `2.32.3`, the environment is ready. If `.venv/` is missing (e.g. a fresh clone), recreate it from `requirements.txt` with the recreate command in Variants, then run step 4 again.
